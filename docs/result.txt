Si falla incluso con Domain Admins, el problema no es de permisos. Es un estado corrupto del objeto msDFSR-ContentSet en AD que el cmdlet no puede sobrescribir.

Vamos a escribir la membresía directamente en AD via ADSI, bypaseando Set-DfsrMembership:

Paso 1 — Verificar si ya existe un objeto de suscripción residual:

$fsxDn = "CN=AMZNFSXEZE56TBV,OU=FSx,OU=Windows,OU=AWS,OU=ExperianExpressCloud,OU=Servers,OU=Systems,DC=gdc,DC=local"
$entry = [ADSI]"LDAP://$fsxDn"
$searcher = New-Object System.DirectoryServices.DirectorySearcher($entry)
$searcher.Filter = "(objectClass=*)"
$searcher.SearchScope = "Subtree"
$searcher.FindAll() | ForEach-Object { $_.Path }
Paso 2 — Verificar el security descriptor del ContentSet:

$contentSetDn = "CN=APC,CN=Content,CN=APXEXPERIAN,CN=DFSR-GlobalSettings,CN=System,DC=gdc,DC=local"
$csEntry = [ADSI]"LDAP://$contentSetDn"
$csEntry.ObjectSecurity.Access |
  Where-Object { $_.AccessControlType -eq "Deny" } |
  Format-Table IdentityReference, ActiveDirectoryRights, AccessControlType -AutoSize
Esto verificará si hay una ACE de denegación explícita sobre el ContentSet que bloquea a todos, incluso Domain Admins. Pásame la salida de ambos.
