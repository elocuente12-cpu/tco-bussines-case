Summary
This guide provides step-by-step instructions for Business Unit application teams to onboard their applications into the EEC Ingress and/or Extranet Cloud Security Stack (CSS). It is intended for application owners, DevOps engineers, and cloud engineers who need to expose applications through the EEC e-Connect infrastructure.

Overview
This guide is intended to give Business Unit application teams an insight on the steps required to onboard their applications into the EEC Ingress and/or Extranet Cloud Security Stack (CSS).

Design
The traffic flow for Internet ingress to an AWS account is located here: Network Diagrams

The traffic flow for Extranet Cloud Security Stack is located here: E-Connect (v3) Egress - Simplified



Prerequisites
If your Application does not have a URL, raise a Request with the Experian Marketing Team to get URL approved for your Application.

If not already requested, raise SSL Certificate Request for your URL with Sectigo.

You can find documentation here on how to create your internal or external domains, create the Entrust certificates required and load them into your AWS accounts.

Step By Step Guide
Step 1 — Raise SNOW Request for Onboarding
Raise a SNOW Request with the GNS Cloud Network Engineering Team to get your application onboarded.

Include details about your application (Account ID, CIDR, Region, and Certificates). A Cloud Engineer will contact you to begin the onboarding process.

Example request: RITM3665502

Form Name:
Request EEC Cloud Account Creation, Migration or Support

Requirements:
Is this request for yourself? Yes
What do you need? Support/Configuration for an existing EEC account
What support do you need? Enable, update or disable internet/extranet access for application (eConnect configuration)
What is the Cloud Service Provider? Select the service provider accordingly
Cloud environment name(s): Select the cloud environment
Short Description: CSS Ingress Onboarding or CSS Extranet OnBoarding
Request Details (brief description of the request):
Please include the following information about your application in the details section.

Frontend Application URL	sandbox-arch-api.serasaexperian.com.br (single domain) or *.api.uat.bis.us.coaas.net (wildcard)	The URL that the client will use to access your application
Frontend Application Port	443	The port that the client will use to access your application, ie: 443
Frontend Application Protocol	HTTPS	Is the application using HTTP or HTTPS?
Frontend SSL Certificate and Private Key (Extranet only)	—	Can be sent to GNS - Cloud Network Engineering team over encrypted email
BACKEND INFORMATION	EXAMPLE(s)	DESCRIPTION
Backend Application URL/IPs	10.99.115.121 (IP) or mn-br-test.external.br.e1platform.io (URL) or ad4df46233822450a89435cf205d510a-b63a952ae52d3170.elb.eu-central-1.amazonaws.com (LB)	The URL or IP addresses that the CSS will use to access your application in AWS or on-prem. This traffic will be internal to Experian and will need to resolve to private IP addresses
Backend Application Port	443	The port that the CSS will use to access your application, ie: 443
Backend Application Protocol	HTTPS	Is the application using HTTP or HTTPS?
Backend Account ID	108167891576	Account ID that the application lives in
Backend Account Name	eec-aws-eits-bu-foo-prod	Name of account
Backend Account CIDR	10.99.115.0/24	CIDR block of the VPC in the account
Environment Type	Prod	Dev / UAT / Prod / etc
Step 2 — Raise SNOW Request for DNS CNAME Record
Raise a SNOW Request to get a CNAME record created for your DNS name with target Ingress LB in AWS or Azure APP GW (v2 endpoint info and v3 endpoint info).

Note: Skip this step if Ingress region is South Africa (For South Africa EEC Team to Raise Snow Request with EITS South Africa Infosec)

Form Name:
Request DNS Management

Requirements:
DNS Request: Add
Internal or External DNS: External
Record Type: CNAME
Target A record to which the CNAME will point (Please put in the FQDN for the A record): Ingress Load Balancer or Azure APP GW Endpoint.
Step 3 — Raise SNOW Request for WAF Protection
Raise a SNOW Request with the WAF Team to get Incapsula/SecureSphere Setup. Attach a note indicating if the request is for CSS Ingress or CSS Extranet.

Form Name:
Request WAF Protection

Requirements:
CloudHosted: Yes or No
Cloud Hosting Provider: AWS, Azure, GCP or OCI
Cloud FQDN (Fully Qualified Domain Name for the Application URL): Ingress Load Balancer or Azure APP GW Endpoint (v2 endpoint info and v3 endpoint info).
Attach a note to the request indicating if request is for CSS Ingress or CSS Extranet.

Enter a justification for your request.

Step 4 — Update DNS CNAME to WAF URL
Raise a SNOW Request to get the CNAME record created in Step 2 updated to the WAF Generated URL from Step 3 above.

Form Name:
Request DNS Management

Requirements:
DNS Request: Modify
Internal or External DNS: External
Record Type: CNAME
Target A record to which the CNAME will point (Please put in the FQDN for the A record): WAF DNS URL provided by WAF Team from the step above.
Step 5 — Validation
GNS Cloud Network Engineering Team completes the onboarding and BU Team validates connectivity.
